# Architecture

## Request lifecycle (one chat turn)

```
POST /v1/chat {session_id, message}
  │
  ├─ session store ─► DialogueState (pickled; in-memory LRU+TTL, Redis-compatible)
  │
  ├─ NLU.parse(text)                                        ~0.6 ms
  │    normalise → tokenise → spell-correct OOV words
  │    gazetteer spans (exact / fuzzy / state codes)
  │    perceptron tagger (Viterbi) → spans not covered by the gazetteer → entity linker
  │    temporal parser → Period
  │    entity masking → TF-IDF → logistic regression → (intent, p, top-3)
  │
  ├─ Dialogue manager (policy)
  │    follow-up / ellipsis rule · pending-frame resume · confidence gate (clarify or LLM)
  │    state.update(slots)  (hierarchical: new region clears states, new state clears towns)
  │
  ├─ Intent handler → Analytics                             1–250 ms
  │    semantic layer → parameterised SQL → DuckDB on Parquet (thread-local cursor, LRU cache)
  │    RCA engine (pandas) · BM25 notes index · glossary
  │
  └─ NLG → markdown + payload (report / table / trend) + suggestions + NLU trace + timings
```

## Data model (synthetic warehouse)

| Table | Grain | Notes |
|---|---|---|
| `fact_sales` | month × territory × SKU | secondary sales (units, gross, net); hive-partitioned by fiscal year |
| `fact_targets` | month × territory × brand | plan at planned prices |
| `fact_field` | month × territory × brand | sanctioned vs active MRs, doctor calls |
| `fact_rx` | month × territory × brand | prescriptions, prescribers |
| `fact_inventory` | month × territory × SKU | stock-out days |
| `fact_distribution` | month × territory × brand | active retailers vs universe |
| `fact_market` | month × state × brand × player | market audit (our brand, competitors, entrants), units |
| `fact_pricing` | month × SKU | PTR, trade discount |
| `field_notes` | free text | MR/ABM/RBM reports, scenario-related and routine |
| `dim_geo`, `dim_brand`, `dim_sku`, `dim_month`, `dim_competitor` | | zone → state → territory; Indian FY |

`_ground_truth.json` lists every planted scenario (cause, brand, region, states, quarter,
severity) and 20 control cells.

### The causal generator

```
market demand (trend × seasonality × noise)
   × Rx share  = base share × response(calls, lagged) × (1 − entrant take) × drift
   = prescriptions
   × retail reach^0.7 × stock availability          (sell-out; prescriptions unaffected)
   × channel loading (quarter-end) × noise           (secondary units)
   × PTR (annual +5%, NPPA cuts)                     (INR value)
```

Because the generator simulates mechanisms, a planted stock-out *produces* flat
prescriptions and falling sales. Nothing about the signature is hard-coded in the data.

## Module boundaries

* `nlp/` knows nothing about the warehouse. Its gazetteer is built from the catalog, and
  `NLU.load(territory_state=...)` injects the warehouse's territory map.
* `analytics/` knows nothing about language. It takes canonical slot values and `Period`s.
* `dialogue/` is the only layer that knows both.
* The LLM fallback returns the *same* schema as the classical NLU, and its strings go
  through the same linker, so the rest of the system cannot tell which produced a parse.

## Safety properties

* No SQL is built from user text; filters are bound parameters (`test_semantic_layer_injection_is_inert`).
* No number in an answer is generated by a model; NLG formats analytics output
  (`test_every_number_in_rca_reply_comes_from_the_report`).
* Assumptions (default period, auto-picked brand or region) are always stated in the reply.
* The semantic layer refuses requests finer than a table's grain (e.g. market share by
  territory) instead of inventing an answer.
